TECHNICAL IMPLEMENTATION
------------------------

Backend API Route (/api/swap/route.js)
------------------------------------
The swap API serves as a secure proxy between frontend and Jupiter infrastructure:

Key Components:
- Token validation whitelist preventing unauthorized swaps
- Decimal conversion handling (SOL: 9 decimals, SPL tokens: 6 decimals)
- Jupiter V2 API integration with authenticated requests
- Comprehensive error handling and logging

Jupiter Integration:
- Single API call to Jupiter Swap V2 endpoint
- Automatic routing optimization including multi-hop paths
- Special handling for SMP's Meteora DAMM2 pools
- Priority fee configuration for fast transaction inclusion

Security Measures:
- Input validation for all parameters
- PublicKey validation for wallet addresses
- Token mint address verification
- Slippage protection (0.5% default)

Frontend Architecture (swap/page.js)
------------------------------------
The frontend handles the complete user journey from swap initiation to confirmation:

Wallet Management:
- Dual wallet detection (external vs embedded)
- Automatic wallet type routing
- Transaction signing adaptation based on wallet type

Transaction Flow:
1. User inputs swap parameters
2. Frontend validates and sends to backend API
3. Jupiter returns pre-built transaction
4. Transaction deserialized and signed
5. Broadcast to Solana network
6. Confirmation status tracking

Error Handling:
- Transaction deserialization validation
- Network error recovery
- Block height expiration handling
- User-friendly error messages

CHALLENGES OVERCOME
------------------

1. SMP Token Integration
   Problem: SMP uses Meteora DAMM2 pools not supported by older Jupiter versions
   Solution: Upgraded to Jupiter V2 API which includes native DAMM2 support
   Result: Seamless SMP swapping with optimal routing

2. Wallet Compatibility
   Problem: Different signing methods for external vs embedded wallets
   Solution: Dual-path architecture with automatic detection
   Result: Single interface supporting all wallet types

3. Modal Overlay Issues
   Problem: Modals appearing below page content due to z-index conflicts
   Solution: Pure inline styling with explicit positioning and high z-index
   Result: Proper overlay behavior across all devices

4. Decimal Precision
   Problem: Different token decimals causing calculation errors
   Solution: BN.js library for precise decimal arithmetic
   Result: Accurate amount calculations for all token types
